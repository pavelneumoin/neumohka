# План реализации презентаций курса «C++ с нуля»

Как из готовых шаблонов конвейерно собрать слайды ко всем урокам курса.

## Что уже готово ✅

- `theme.css` — macOS-тема Marp (светлый минимализм, код-окна, акцент-градиент)
- `templates.md` — библиотека из 15 макетов слайдов (обложка, разделитель, оглавление, контент, две колонки, код, карточки, сравнение, таблица, цитата, тезис, число, картинка, задание, финал)
- `deck.md` — пилотная вступительная презентация (16 слайдов), собрана в PDF
- **Визуальный агент-ревьюер** — субагент рендерит слайды в PNG, осматривает «глазами» и чинит вёрстку
- `course-plan.md` — учебный план (6 модулей, ~17 уроков)

## Структура папок (целевая)

```
slides/cpp-course/
├── theme.css            # одна тема на весь курс
├── templates.md         # справочник макетов
├── _lesson-template.md  # болванка нового урока (создаём в фазе 1)
├── deck.md              # вводная презентация
├── lessons/
│   ├── 01-1-hello-world/lesson.md
│   ├── 01-2-output/lesson.md
│   ├── 02-1-variables/lesson.md
│   └── ...              # по уроку из course-plan.md
└── build/               # собранные PDF (или рядом с lesson.md)
```

## Конвейер: как делается один урок

1. **Копируем болванку** `_lesson-template.md` → `lessons/NN-slug/lesson.md`
2. **Наполняем контентом** из `course-plan.md` (цель → теория → код → практика → задание), используя готовые макеты из `templates.md`
3. **Собираем PDF:** `npx marp lessons/NN-slug/lesson.md --theme theme.css --allow-local-files -o lessons/NN-slug/lesson.pdf`
4. **Прогоняем визуального агента** — рендер в PNG, осмотр, авто-фикс вёрстки
5. **Ревью человеком (Павел)** — проверка смысла, примеров, темпа
6. **Готово** → урок уходит в `library/` сайта «Неумошка»

## Чек-лист «слайд-дек готов»

- [ ] Контент соответствует целям урока из `course-plan.md`
- [ ] Каждый код-пример компилируется и запускается (проверен в g++)

- [ ] Визуальный агент не нашёл дефектов вёрстки

## Технические заметки

- **Сборка всех уроков разом** (фаза 1): добавить в `package.json` скрипт, который проходит по `lessons/**/lesson.md` и рендерит каждый в PDF.
- **Рендер на Linux** требует Chromium: `export CHROME_PATH="$(node -e "console.log(require('puppeteer').executablePath())")"` перед `marp`.
- **Картинки/скриншоты** кладём рядом с уроком и вставляем `![](pic.png)`; запуск с `--allow-local-files`.
- **Рабочие листы** (worksheet.pdf) к урокам — отдельный мини-шаблон, можно добавить в фазе 3, если нужны печатные задания.

## Решения (зафиксировано с Павлом)

1. **Длительность урока — 45 минут** → деки ~12–14 слайдов.
2. **Рабочие листы нужны** → печатный шаблон `worksheet.css` (A4) + `worksheet.md` к каждому уроку.
3. **Только PDF** — HTML-версии уроков не делаем.
4. **Упор на практику с сюжетом** — 4–6 задач на урок с интересной детям историей.

## Проверка PDF (важно!)

Визуальный агент смотрит PNG (рендер Chromium) — но некоторые баги видны **только в PDF** на «неродных» просмотрщиках (PDFKit на iPad). Пример: широкая тень с большим размытием склеивалась в серый блок. Поэтому в пайплайн добавлен PDF-точный рендер:

```bash
npm run check -- templates.pdf 12 2   # отрендерить стр.12 движком pdf.js в PNG
```

Используется `scripts/pdf-to-png.mjs` (pdf.js + canvas).

**Три класса багов, которые ловятся только в PDF (не на PNG):**

1. **Серый блок за карточками** — широкие `box-shadow` Chromium запекает в растровые SMask-маски, PDFKit (iPad) рисует их серым. Решение: `--shadow: none`, глубину держим рамками (`--ring`). Никаких blur-теней.
2. **«Битые картинки» эмодзи** — Marp по умолчанию грузит эмодзи как Twemoji-картинки **с CDN по сети**; при сбое сети в PDF появляется битая иконка. Решение: пакет `@twemoji/svg` + `marp.config.mjs` направляет Marp на локальные SVG (офлайн, детерминированно). Страж: `npm run check:emoji` (входит в `build`).
3. **Распухшая плашка `.pill`** — относительный `font-size` наследовал кегль от `h1`. Решение: абсолютный размер у `.pill`.
